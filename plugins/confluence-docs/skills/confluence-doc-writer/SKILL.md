# Confluence 문서 작성

Claude와 Codex에서 사용하는 이식 가능한 문서 작성 스킬이다. 기본 전달 방식은 **본문 HTML 소스를 Confluence의 HTML 소스 입력 기능에 붙여넣기**다. 사용자의 회사 환경에서 동작한 방식에 맞춰 `<body>` 안쪽 내용만 출력한다. 전체 HTML 문서나 `<body>` 태그를 복사할 필요가 없어야 한다.

기본 비교 형식은 **변경 전후는 As-Is / To-Be**, **대안은 1안·2안·3안을 열로 둔 표**다. 비교할 내용이 있으면 [비교 표 규칙](references/comparisons.md)을 적용한다. 문서와 질문은 [문체 규칙](references/writing-style.md)에 따라 짧고 구체적으로 쓰며 과장과 막연한 표현을 줄인다. 명시한 사용자 양식·문구·구성은 기본 규칙보다 우선한다.

## 사실 기준

문서는 사용자 답변과 실제 읽은 자료에 근거해 쓴다. 해당 업무의 배경·원인·효과·완료 범위·계획을 일반 지식이나 그럴듯한 추측으로 보충하지 않는다. 작업 완료만으로 효과를, 사건의 선후 관계만으로 원인을 확정하지 않는다. 템플릿과 예시의 내용은 현재 업무의 사실이 아니다.

모르는 필수 정보는 먼저 질문한다. 사용자가 설명한 기대 효과·목표·계획은 그 상태로 구분하며, 모델의 추측에 `예상`·`가정`·`~로 보인다`를 붙여 넣지 않는다. 새로운 업무 대안·가설은 제안을 요청받았을 때만 확인된 사실과 분리해 다룬다. 문장·표·그림 구성을 맡긴 것은 사실을 만들어도 된다는 뜻이 아니다. 이 기준은 요약, 비교 표, 그림의 요소·연결선·캡션과 저장·재개 내용에도 적용한다. 상세한 근거 대조는 [수치·근거 검토 규칙](references/fact-review.md)을 따른다.

## 작업 방식

“템플릿 목록” 요청은 [템플릿 적용 규칙](references/templates.md)에 따라 사용 가능한 양식을 안내하고 문서 작성 질문은 시작하지 않는다. 기존 문서의 특정 부분 수정은 [부분 수정 규칙](references/editing.md)을 적용한다.

“여기까지 저장”, “이어서 작성”, “저장한 문서 목록” 요청에는 [진행 저장·재개 규칙](references/progress.md)과 [저장 도구](scripts/progress.py)를 사용한다. 기본 위치는 현재 작업 폴더의 `.confluence-docs/drafts/`이며 저장된 회사 자료를 공개 저장소나 배포물에 추가하지 않는다. 새 채팅에서는 저장 파일을 읽고 재개하며 자동 기억을 보장하지 않는다.

1. 사용자가 제공한 메모, 파일, 코드, 기존 문서에서 목적·독자·핵심 사실을 파악한다. 기존 문서는 변경 전에 실제 원본을 고유 파일명으로 보관하고 의도와 용어를 유지한다. 요청 언어를 따르고 별도 지정이 없으면 한국어로 쓴다.
2. [템플릿 적용 규칙](references/templates.md)을 읽고 명시한 경로·양식 또는 한국어 문서 이름으로 템플릿을 선택한다. 공개 양식의 이름·별칭·항목별 작성 기준은 [템플릿 목록](assets/templates/catalog.json)에 있다. 사용자 양식의 기준은 그 파일에서 확인하며 공개 양식의 기준으로 덮어쓰지 않는다. 회의록 양식을 지정하지 않았으면 제공된 내용의 안건 수·상세도·복잡성을 보고 한 표 형식 또는 안건별 상세 형식을 직접 선택한다. 선택 이유만 짧게 알리고 양식 선택 질문이나 승인을 추가하지 않는다. 필요한 사실은 계속 확인한다. 그 외에 양식이 없으면 [문서별 구성](references/document-types.md)에서 요청에 맞는 부분만 선택하며 문서 목적이나 양식 선택이 애매하면 확인한다. 모든 문서에 같은 목차를 강제하지 않는다.
3. [대화로 정보 채우기](references/intake.md)를 읽고 템플릿 항목별로 확인된 사실과 부족한 정보를 정리한다. 애매한 내용을 임의로 판단하지 않고 필요한 질문을 한 번에 1~3개씩 하며 답변을 반영한다. 정보가 충분해지기 전에는 최종 문서 파일을 만들지 않는다. `확인 필요`나 `가정`으로 빈칸을 채우는 것으로 질문을 대신하지 않는다. 담당자·일정·측정값·명령 실행 결과·출처를 만들어내지 않는다. 이미 충분한 자료가 있으면 사실 질문을 반복하지 않는다. 필요한 구성 선택은 5단계에서 다룬다.
4. [수치·근거 검토 규칙](references/fact-review.md)에 따라 주요 주장과 수치의 근거·계산·종류를 대조한다. Python이 있으면 [검토 도구](scripts/review_facts.py)를 사용한다. 불일치나 애매함이 남으면 해당 질문부터 다시 확인하고 자동 수정하지 않는다. 정보와 검토가 충분해지면 [붙여넣기 출력 규칙](references/paste-format.md)을 읽고 전달 형식을 확인한다. 짧은 설명은 짧게 유지하고 운영 문서는 실제 실행에 필요한 조건과 확인 방법을 포함한다.
5. [시각화 구성·다이어그램 규칙](references/diagrams.md)을 읽고 표·그림 구성을 판단한다. 의미 있게 다른 구성이 있으면 그림 수·위치·목적을 포함한 구성안을 먼저 제시하고 선택을 받는다. 표만으로 충분하거나 사용자가 이미 구성·수량을 정했거나 판단을 맡긴 경우에는 불필요한 선택 질문 없이 진행한다. 사실 정보와 필요한 구성 선택이 정리되면 `<slug>.body.html`과 같은 내용의 `<slug>.md`를 사용자 작업 폴더에 생성한다. [복사 미리보기·내용 대조 규칙](references/output-tools.md)에 따라 [미리보기 도구](scripts/build_preview.py)로 본문 HTML 소스 복사 버튼이 있는 `<slug>.preview.html`도 함께 만든다. 사용자가 미리보기를 제외하라고 하면 그 요청을 따른다. 위치 표시나 구성안의 수량만으로 불필요한 그림을 생성하지 않는다. 생성한 그림은 PNG와 편집용 `.drawio` 원본을 함께 제공한다. HTML 코드 블록을 보여주는 것만으로 파일 생성을 대신하지 않는다.
6. [출력 검사 도구](scripts/validate_body.py)로 본문 HTML을 검사하고 [내용 대조 도구](scripts/compare_documents.py)로 HTML·Markdown을 비교한다. 불일치와 지원 밖 표현의 처리는 [출력 도구 규칙](references/output-tools.md)을 따른다. 생성된 요약·본문·표의 주요 수치와 근거 표현도 재대조하고 불일치가 있으면 최종 전달 전에 확인한다. 비교 표의 행·열과 선택한 그림 구성, 과장·막연한 표현도 검토한다. 제목 계층, 표, 링크, 코드와 원문의 사실 일치도 확인한다. 기존 문서 수정에는 보존한 실제 원본과 수정본을 [수정 내역 도구](scripts/summarize_changes.py)로 비교해 별도 `<slug>.changes.md`를 제공한다. 가능하면 미리보기 파일을 브라우저로 열어 확인한다. 도구 검사나 브라우저 표시만으로 회사 HTML 소스 기능의 동작을 검증했다고 주장하지 않는다.
7. 최종 응답에는 파일 링크와 아래 사용법을 짧게 제공한다. 문서 내용에 설치 안내나 모델의 작업 설명을 섞지 않는다.

## 전달 계약

- 기본 산출물 `<slug>.body.html`은 UTF-8 HTML 조각이다. `DOCTYPE`, `<html>`, `<head>`, `<body>`, `<title>`, `<meta>`, `<style>`, `<script>`, `<main>` 래퍼와 Markdown 코드 펜스를 넣지 않는다. 첫 내용은 실제 본문 문단이나 섹션 제목이다. 파일 전체를 그대로 복사할 수 있어야 한다.
- 페이지 제목은 최종 안내와 Markdown 상단에 제공하고 Confluence 제목 필드에 입력한다. 본문에는 페이지 제목을 중복하지 않으며 섹션은 `<h2>`부터 시작한다.
- 사용법: `.preview.html 열기 → 본문 HTML 소스 복사 → Confluence 제목 입력 → HTML 소스 입력 창에 붙여넣고 적용 → 표·코드·링크 확인`. 미리보기가 없으면 `.body.html`을 텍스트/코드 편집기로 열어 소스 전체를 복사한다.
- `.preview.html`은 브라우저 확인·본문 소스 복사용 전체 HTML 문서다. 본문 파일을 기준으로 만들고 외곽 태그·미리보기 CSS·복사 제어 스크립트는 이 파일에만 둔다. 회사 입력 창에는 `.body.html`의 원문만 넣는다.
- 파일 생성이 불가능하면 본문 조각만 담은 하나의 `html` 코드 블록을 제공한다. 제목과 사용법은 블록 밖에 두고 코드 펜스를 제외한 내부 소스만 복사하도록 안내한다. 파일을 만들었다고 주장하지 않는다.
- 이미지가 있으면 이미지 파일 목록과 삽입 위치를 제공한다. 로컬 이미지가 HTML 소스 입력만으로 Confluence에 첨부된다고 가정하지 않는다. 본문에는 확인된 첨부 URL만 사용하고 URL이 없으면 그림 삽입 위치를 문단으로 표시한다.
- HTML 소스 입력 기능은 설치 앱·편집기별로 지원 범위가 다르다. 사용자 환경의 본문 조각 방식에 맞추되 모든 Confluence에 기본 제공되는 기능이라고 주장하지 않는다. 대상 환경이 불명확하면 기본적인 제목·문단·목록·표 중심으로 만든다.

## 범위와 다른 출력 요청

템플릿은 스킬 설치 폴더 밖에 두고 경로나 이름으로 선택할 수 있다. 회사 템플릿은 회사 작업 폴더의 `.confluence-docs/templates/` 또는 사용자가 지정한 별도 폴더에서 읽는다. 스킬을 업데이트해도 사용자 템플릿을 덮어쓰지 않는다. 템플릿 파일을 수정하는 요청이 없다면 읽기만 한다.

실제 회사 템플릿을 공개 스킬 저장소·Release·샘플 파일에 복사하지 않는다. 회사에서는 그곳에서 허용된 도구와 파일 접근 범위 안에서 적용한다. 개인 컴퓨터의 경로가 회사 환경에서도 존재한다고 가정하지 않는다.

이 스킬은 문서를 작성하는 데 집중한다. 문서 작성 요청만으로 Confluence에 접속하거나 페이지를 생성·게시·덮어쓰지 않는다. 사용자가 게시까지 명시적으로 요청했다면 사용 가능한 연결 도구와 해당 권한을 확인하고 진행한다.

사용자가 일반 편집기의 서식 붙여넣기를 지정하면 미리보기에서 렌더링된 본문을 복사하는 방식을 안내한다. HTML 소스 입력 방식과 구분한다. `.docx` 가져오기, API storage 형식 또는 레거시 wiki markup을 지정하면 해당 요청을 우선한다. 대상 제품·편집기에서 그 형식을 지원하는지 확인하고 적합한 도구를 사용한다. 일반 HTML을 Confluence storage 형식이라고 부르거나 `.md` 파일의 기본 가져오기를 보장하지 않는다. 레거시 매크로 문법은 기본 본문에 넣지 않는다.
