대상·환경, 관측한 현상, 최초 확인 시각, 현재 상태와 그 확인 시점을 먼저 확인한다. 실제 발생 시각과 최초 확인 시각은 구분하고 발생 시각을 모르면 역산하지 않는다. 제공된 시각의 날짜·시간대가 애매하거나 기록이 충돌하면 질문한다.
영향은 확인된 업무·서비스·범위만 적는다. 영향 규모·지속시간·데이터 유실·연관 시스템 장애를 추정하지 않는다. 모르는 영향은 사용자와 확인 중 표현을 합의한다.
대응 경과는 실제 조치와 관측 결과를 시간순으로 기록한다. 원인이 해결됐는지와 서비스가 복구됐는지는 구분하며 재시작·프로세스 기동만으로 정상 복구를 확정하지 않는다. 조치를 아직 하지 않았다면 확인된 상태만 쓰고 빈 표를 생략한다.
로그·오류 메시지는 실제 제공된 내용을 그대로 인용하고 필요한 범위만 코드 블록으로 넣는다. PID·버전·설정값·지표·로그 링크는 관련 자료가 있을 때만 포함한다. 별도 근거 자료가 없으면 해당 블록을 생략하고 로그에 없는 메시지나 접근하지 못한 링크의 내용을 만들지 않는다.

표로 충분하면 그림을 만들지 않는다. 실제 설정·절차 변경을 비교할 때만 기존 목차 안에 As-Is / To-Be 표를 넣으며 정상·장애 흐름이나 수치를 새로 만들지 않는다.
