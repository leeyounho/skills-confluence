# {{모듈명}} 업무 진행현황

<!-- 작성 안내
목적: 며칠 간격 또는 주 단위로 모듈원들의 과제와 일회성 업무를 구분해 확인한다. 상단 보고 기준 표와 요약은 만들지 않고 본문 표부터 시작한다. 제공된 기준일·기간을 표시할 필요가 있으면 제목에 짧게 덧붙인다. 표 대신 긴 메타 정보 문단을 추가하지 않는다.
과제 진행 현황은 여러 차례의 점검에서 진행·결과·다음 단계의 지속적인 follow-up이 필요한 과제를 기록한다. 이 양식의 Action Item은 개별 요청이나 처리를 마치면 종료되는 일회성 업무를 기록한다. 업무명이나 기간만으로 구분을 추측하지 않으며 범위가 애매하면 사용자에게 확인한다.
같은 모듈원에게 두 종류가 함께 있으면 두 표에 각각 해당 업무를 기록한다. 한 종류만 요청했거나 해당 종류가 없다고 확인되면 불필요한 목차와 빈 표를 생략한다. 자료가 빠졌다는 이유로 업무 없음으로 판단하지 않는다. 하나의 업무를 두 표에 중복하지 않는다. 과제에 속한 작업이라면 확인된 과제명과의 연결을 유지한다.
과제 표는 과제 / 담당 / 상태 / 진행현황·이슈 / 다음 확인사항·목표일이다. 같은 행에서 진행·결과·이슈·지원 요청과 다음 확인사항을 읽을 수 있게 한다. 진행현황·이슈 셀에는 실제 있는 내용만 진행: … / 이슈: … / 지원 요청: …처럼 줄을 나눠 짧게 기록한다. 한 과제의 담당·세부 작업이 여러 개면 실제 책임과 진행 내용의 연결을 유지한다.
Action Item 표는 업무 / 담당 / 상태 / 처리 내용·결과 / 기한이다. 단순 처리 업무에 과제 단계·진행률·장기 계획을 만들지 않는다. 완료 업무도 요청한 기간의 실제 처리 결과라면 포함한다. 완료 업무의 기한은 제공된 경우에만 적고 자료가 없으면 셀을 비워두며 이미 끝난 작업의 기한을 추가 질문하지 않는다. 계속 확인해야 하는 과제로 바뀐 경우에는 사용자에게 확인한 뒤 이동하고 기존 작업 내용을 보존한다.
상태는 제공된 표현을 유지한다. 자료에 없는 완료·지연·진행률을 추정하지 않는다. 담당·상태·실제 진행 또는 처리 결과, 미완료 업무의 기한이나 과제의 다음 확인사항이 빠지거나 애매하면 필요한 값만 질문한다. 미정·업무 없음·추가 확인 없음은 사용자가 확인한 상태로만 적는다. 상태가 아직 확인되지 않았다는 답은 업무 대기로 바꾸지 않는다.
이전 보고서가 있으면 실제 파일과 기준일을 읽고 이번 기간의 변화·새 작업·완료 작업을 확인한다. 이전 상태를 확인 없이 현재 사실로 재사용하거나 이전 보고서를 덮어쓰지 않는다. 이전 자료가 없으면 지난 실적이나 변경 전 상태를 만들지 않는다. 기간이 애매해 이번 진행을 판단할 수 없을 때만 확인하고 주간 요청만으로 월~금 기간을 가정하지 않는다. 업무 방식의 전후 비교가 필요할 때만 확인된 내용을 As-Is / To-Be 표로 추가한다.
이슈·영향·지원 요청은 해당 과제의 진행현황·이슈 셀에, 확인할 결과·필요한 대응과 제공된 담당·기한은 같은 행의 다음 확인사항·목표일 셀에 적는다. 과제 담당과 지원 담당이 다르면 제공된 역할을 구분한다. 여러 과제에 공통인 사안은 실제 관련 과제의 행마다 짧게 표시하고 연결이 애매하면 확인한다. Action Item에 속한 이슈·지원 요청은 그 업무의 처리 내용·결과 셀에 적고 다른 과제에 옮기지 않는다.
이슈 및 지원 요청, 다음 확인 계획의 별도 목차·표를 만들지 않는다. 이전 기록에 따로 있던 내용은 누락 없이 해당 업무의 행으로 옮기고 어느 업무에 속하는지 애매하면 질문한다. 자료에 없는 위험·이슈 없음·약속·일정을 만들지 않는다. 실제 이슈가 없으면 해당 문구를 생략하며 주기·다음 확인일을 필수 질문으로 늘리지 않는다. 인원·건수·완료율이나 그림을 채우려고 내용을 만들지 않는다.
HTML 표의 여러 항목은 목록이나 br, Markdown에서는 br로 구분하고 세로줄을 이스케이프한다. 셀 병합·중첩 표는 사용하지 않는다. 회사에서 지정한 양식과 부분 수정 범위가 우선한다.
