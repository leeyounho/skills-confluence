# 비교 표의 기본 형식

변경 전후 비교는 As-Is / To-Be, 대안 비교는 1안·2안·3안을 열로 둔 표가 기본이다. 별도 회사 프로필이나 설정 파일이 없어도 적용한다. 사용자 요청이나 지정 양식의 필수 열이 다르면 그 지정을 따른다. 양식의 필수 목차·열을 지우지 않는다.

## 변경 전후: As-Is / To-Be

현재 문제와 개선 방식, 기존 절차와 변경 절차, 전후 지표를 같은 항목의 행에서 비교한다. 비교할 내용이 있는 섹션에 표를 넣고 새 목차를 강제로 추가하지 않는다.

| 비교 항목 | As-Is | To-Be | 효과·영향 |
| --- | --- | --- | --- |
| 처리 방식 | 확인된 기존 방식 | 확인된 변경 방식 | 확인된 차이와 영향 |
| 운영 절차 | 확인된 기존 절차 | 확인된 변경 절차 | 작업에 미치는 영향 |
| 처리시간 | 기존 값과 단위·기준 | 변경 값과 단위·기준 | 확인된 변화 |

위 행은 형식 예시다. 실제 비교 항목만 넣고 자료가 없는 예시 행은 만들지 않는다. 효과·영향 열은 근거가 있고 표 이해에 도움이 될 때 사용한다. 세 열만으로 충분하면 비교 항목 / As-Is / To-Be로 작성한다.

- To-Be가 이미 반영된 결과인지 제안·계획인지 구분한다. 셀이나 설명에서 `실측`, `목표`, `예상`, `계획`을 필요한 곳에 표시한다. 기대 효과를 실적으로 바꾸지 않는다.
- 전후 수치는 단위·기간·대상 범위를 맞춰 읽을 수 있게 쓴다. 비교 기준이 애매하면 [수치·근거 검토](fact-review.md)에 따라 질문한다. 수치가 없는 변경에는 가짜 지표를 추가하지 않는다.
- 기존 방식이나 변경 방식이 확인되지 않았는데 표를 완성하려고 추측하지 않는다. 필요한 사실부터 질문한다.
- 같은 비교를 다른 섹션의 표·그림으로 반복하지 않는다. 요약은 차이와 결과만 요약한다.

## 대안: 1안 / 2안 / 3안

판단 기준을 행, 실제 대안을 열로 둔다. 대안에 이름이 있으면 `1안: 기존 방식 유지`처럼 번호와 이름을 함께 쓴다. 원래 대안의 이름과 의미를 바꾸지 않는다.

| 판단 기준 | 1안: 대안 이름 | 2안: 대안 이름 | 3안: 대안 이름 |
| --- | --- | --- | --- |
| 구성·방식 | 확인된 내용 | 확인된 내용 | 확인된 내용 |
| 장점 | 확인된 장점 | 확인된 장점 | 확인된 장점 |
| 단점·리스크 | 확인된 제약 | 확인된 제약 | 확인된 제약 |
| 비용·일정 | 확인된 조건 | 확인된 조건 | 확인된 조건 |
| 적합한 조건 | 적용 조건 | 적용 조건 | 적용 조건 |

- 실제 대안이 두 개면 1안·2안만 비교한다. 세 안을 채우려고 새 대안을 만들지 않는다. 대안 추가를 요청받았을 때만 새 제안을 기존의 확정 대안과 구분해 만든다.
- 같은 행에는 같은 기준과 구체성으로 내용을 쓴다. 한 안의 장점만 자세히 쓰거나 근거 없는 점수·등급·순위를 넣지 않는다.
- 장점·리스크·적합한 조건도 해당 안의 자료에 근거한다. 일반적으로 알려진 장단점을 회사의 확인된 조건이나 검증 결과처럼 추가하지 않는다. 새 대안 제안에 필요한 미확인 조건은 별도로 확인한다.
- 비용·일정 등 판단에 필요한 자료가 없으면 질문한다. 사용자가 미정으로 기재하라고 한 경우에는 그 상태를 표시한다. 비교에 관계없는 기준은 넣지 않는다.
- 권고안은 우선순위와 제약 조건이 확인된 경우에만 이유를 적는다. 기준이 애매하면 무엇을 우선할지 묻고 `최적`, `압도적`, `가장 효과적` 같은 표현으로 선택을 대신하지 않는다.

## 표와 그림

단순한 차이나 대안의 장단점은 표를 먼저 사용한다. 연결 관계·분기·전체 구조를 표만으로 이해하기 어려울 때 [시각화 구성 제안](diagrams.md)을 적용한다. 비교 표와 그림이 같은 정보만 반복하면 그림을 생략한다. 최종 표는 단순한 HTML table로 작성하고 셀 병합·중첩 표는 피한다.
