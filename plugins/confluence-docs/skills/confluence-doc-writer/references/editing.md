# 문서 일부 수정

“효과만 수정”, “향후계획의 일정 변경”처럼 범위를 지정한 요청에 적용한다.

1. 기존 문서 파일과 대화의 확정 사실을 읽고 수정할 섹션을 특정한다. 원본이 없거나 같은 제목의 섹션이 여러 개여서 대상을 구분할 수 없으면 필요한 원본·대상을 확인한다. 기존 문서를 보지 않고 재현했다고 주장하지 않는다.
   수정 전 원본은 [수정 내역 규칙](output-tools.md)에 따라 별도 파일로 보존한다. 수정 후 파일로 이전 내용을 재구성하지 않는다.
2. 변경 요청의 새 사실을 해당 항목에 반영한다. 값의 의미가 애매하거나 기존 사실과 충돌하는데 어느 것이 최신인지 분명하지 않으면 그 항목만 질문한다. 명확한 정정은 기존 값을 대체하고 이미 답한 다른 항목을 다시 질문하지 않는다.
3. 요청한 섹션과 그 내용을 요약한 Executive Summary·핵심 요약 등 기존 자동 요약 항목만 필요한 만큼 수정한다. 요약 항목이 없는 양식에는 새로 추가하지 않는다. 요청과 관계없는 문장·표·목차·용어·확정 사실은 유지한다. 요약의 변경도 새 내용을 반영하는 최소 범위로 한다. 다른 본문 섹션에도 충돌이 생겨 추가 수정이 필요한 경우 영향 범위를 설명하고 사용자에게 확인한다.
4. 기존 `.body.html`과 `.md`를 함께 수정하고, `.preview.html`은 수정된 본문의 복사 미리보기로 갱신한다. 사용자가 미리보기를 제외하라고 했으면 생략한다. 변경하지 않은 표·문체·그림 구성도 유지한다. 새 기본 규칙을 적용하려고 부분 수정 범위를 전체 문서로 넓히지 않는다. 그림의 내용에 영향이 없다면 다시 생성하지 않는다. 영향이 있으면 해당 그림만 갱신한다. 사용자가 그림 구성 변경을 요청한 경우에만 구성안을 다시 제시한다.
5. 변경하지 않은 섹션과 기존 버전을 비교하고 HTML 검사·HTML/Markdown 내용 대조를 실행한다. 수정한 사실·수치와 관련 요약은 [수치·근거 검토](fact-review.md)를 적용한다. 불일치가 남으면 확인하고 최종 전달을 보류한다. [출력 도구 규칙](output-tools.md)에 따라 실제 원본과 수정본에서 `<slug>.changes.md`를 생성해 추가·변경·삭제 항목을 별도로 전달한다. 보고서를 본문에 삽입하지 않으며 변경 이유·효과는 추정하지 않는다. 전달 안내에는 수정한 항목과 연동해 바뀐 요약를 짧게 알려준다. 페이지를 자동 게시하지 않는다.

중간 초안을 수정하는 경우에는 이미 해결된 정보와 미확정 사항을 유지하며 수정한 부분의 준비 상태만 갱신한다. 수정 요청 자체를 전체 문서의 정보 수집을 처음부터 다시 시작하라는 뜻으로 해석하지 않는다.
