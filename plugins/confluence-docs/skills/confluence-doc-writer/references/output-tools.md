# 복사 미리보기·내용 대조·수정 내역

파일을 만들거나 수정할 때 적용한다. 도구는 Python 표준 라이브러리만 사용하며 추가 패키지·회사 GitHub Actions·계정 연결이 필요 없다. 문서 작성 사실은 기존 정보 수집·근거 검토 규칙으로 확인한다.

## 본문 HTML 복사 미리보기

기본은 `.body.html`과 `.md`에 더해 복사 버튼이 있는 `.preview.html`을 함께 제공한다. 사용자가 미리보기를 제외하라고 했거나 파일을 만들 수 없으면 기존 전달 방식을 따른다.

```text
python -X utf8 <스킬폴더>/scripts/build_preview.py <문서.body.html> --title "페이지 제목" --output <문서.preview.html>
```

- 미리보기의 **본문 HTML 소스 복사** 버튼은 `.body.html`에서 읽은 원문을 복사한다. 화면의 DOM·제목·버튼·미리보기 CSS를 복사하지 않는다. 본문 파일은 변경하지 않는다.
- 브라우저가 자동 복사를 허용하지 않으면 소스 영역을 열고 선택한다. 사용자는 Ctrl+C 또는 Cmd+C로 복사한다. **소스 선택** 버튼도 제공한다.
- 본문을 수정할 때마다 미리보기를 다시 생성한다. 오래된 미리보기의 소스를 최종 전달하지 않는다. 미리보기에서 로컬 그림 경로만 조정할 수 있으나 복사용 원문 데이터는 변경하지 않는다.
- Python이 없으면 같은 구조의 미리보기를 직접 만들 수 있다. 복사 원문을 JSON 문자열로 저장하고 `<`를 JSON의 `\u003c`로 이스케이프해 script 태그가 중간에 닫히지 않게 한다. 클릭 처리에는 해당 원문만 사용하며 자동 복사 실패 시 소스를 선택한다. 만들어진 파일과 복사 원문이 일치하는지 확인한다.
- 미리보기의 script·CSS·제어 버튼은 미리보기에만 둔다. Confluence HTML 소스 입력 창에 넣는 것은 복사된 본문 조각이다. 브라우저 확인은 회사 Confluence 기능 검증과 구분한다.

## HTML·Markdown 내용 대조

작성·부분 수정 후에는 HTML 구조 검사와 함께 [내용 대조 도구](../scripts/compare_documents.py)를 실행한다. 두 입력 파일은 읽기만 한다.

```text
python -X utf8 <스킬폴더>/scripts/compare_documents.py <문서.body.html> <문서.md>
```

지원 범위는 일반 제목, 문단, 목록, 단순 표, 링크, fenced code와 기본 인라인 서식이다. 제목 계층·항목 순서·표의 행과 셀·문장·코드·링크 대상을 비교하므로 주요 수치·단위·결정 문구가 달라도 불일치가 된다.

- 종료값 `0`: 비교 대상 내용 일치. `1`: 차이 발견. `2`: 입력 오류 또는 지원하지 않는 표현. JSON의 differences에서 양쪽 위치와 내용을 읽는다.
- Markdown 상단 페이지 제목은 본문 HTML에 중복하지 않으므로 비교에서 제외한다. 강조·공백·일반 문단 줄바꿈·코드 펜스의 언어 표기 같은 형식 차이는 정규화한다. 코드 블록 내부 줄바꿈과 공백은 보존하며 끝의 줄바꿈 차이는 제외한다.
- 이미지 원본·URL·대체 텍스트와 `그림 삽입 위치:` 안내는 자동 대조에서 제외한다. 캡션 문장은 비교한다. 실제 그림·캡션·첨부 URL·삽입 위치 대응은 별도로 읽고 확인한다.
- 참조 링크·각주·들여쓰기 코드·셀 병합·중첩 표 같은 지원 밖의 표현은 수동 대조한다. 사용자 양식이나 사실을 삭제해 검사에 맞추지 않는다. 잘못 닫힌 태그나 코드 펜스, 잘못 나뉜 표 등 출력 오류는 수정한다.
- 이미 확인된 원문이 분명한데 한쪽 산출물만 갱신되지 않았다면 해당 파일을 동기화한다. 어느 내용이 맞는지 애매하거나 출처가 충돌하면 사용자에게 확인하고 임의로 양쪽 값을 통일하지 않는다.
- 일치 결과는 양쪽 문서가 동일한 내용을 담는다는 검사다. 그 내용의 사실성·인과관계·완료 상태나 모든 Markdown 문법의 렌더링을 입증하지 않는다. Python이 없으면 동일 항목을 수동으로 대조하고 자동 검사 실행을 주장하지 않는다.

## 수정 내역 요약

기존 문서를 수정할 때 기본으로 별도 `<slug>.changes.md`를 제공한다. 새 문서 작성에는 빈 수정 내역 파일을 만들지 않는다.

1. 수정 전에 읽은 원본을 작업 폴더의 `.confluence-docs/drafts/originals/` 아래 고유 파일명으로 보관한다. 이미 제공된 이전 버전이 있으면 그 파일을 사용한다. 원본과 저장 위치는 공개 저장소·배포물에 넣지 않는다.
2. 요청 범위의 문서와 관련 요약를 수정하고 내용 대조를 마친다.
3. 같은 형식의 이전·이후 파일로 [수정 내역 도구](../scripts/summarize_changes.py)를 실행한다. 기본은 `.md`끼리 비교하며 본문 `.html`끼리도 가능하다.

```text
python -X utf8 <스킬폴더>/scripts/summarize_changes.py <수정전.md> <수정후.md> --output <문서.changes.md>
```

수정 내역은 추가·변경·삭제 구분, 위치, 이전 내용, 변경 내용을 실제 파일에서 정리한다. 원본 입력은 수정하지 않으며 보고서로 원본을 덮어쓸 수 없다. 문서 제목도 Markdown 원본끼리 비교할 때 포함한다. 본문 내용의 차이를 기록하며 서식만의 변경과 이미지 경로는 자동 요약에서 제외한다.

변경 이유·기대 효과는 도구가 추정하지 않는다. 설명이 필요하면 사용자가 제공한 이유만 덧붙인다. 그림 자체나 첨부의 변경은 실제 이전·이후 파일을 확인해 별도로 기록한다. 원본이 없으면 이전 내용을 재구성하거나 비교를 완료했다고 주장하지 않는다. 지원 밖의 문법은 실제 파일을 수동 비교해 같은 항목으로 작성한다.

수정 내역은 검토용 별도 파일이다. Confluence 본문에 이 표를 자동 삽입하거나 문서의 큰 목차를 늘리지 않는다. 예상 밖의 섹션 변경이 있으면 원본과 요청 범위를 확인하고 고친다.
