# 보고서 문체

이 규칙은 문서 본문, 요약, 표·그림의 문구와 작성 중 질문에 기본으로 적용한다. 사용자가 지정한 문서명·고정 문구·전문 용어는 유지한다. 단어 목록을 기계적으로 삭제하거나 전문 용어의 의미를 바꾸지 않는다.

## 구체적으로 쓰기

- 무엇을 바꿨는지, 어디까지 완료했는지, 어떤 결과를 확인했는지 쓴다. 일반적인 장점이나 기대를 덧붙여 분량을 채우지 않는다.
- 짧고 직접적인 문장으로 쓴다. `변경했다`, `확인했다`, `검토 중이다`, `진행할 예정이다`처럼 상태를 분명히 한다. 문서에 맞으면 `변경 완료`, `일정 미정` 같은 짧은 표 문구도 쓴다.
- `실측 결과`, `사용자 정성 평가`, `기대 효과`, `미정`을 구분한다. 기대 효과는 사용자·자료가 제시한 내용이어야 한다. `~로 예상된다`·`~로 보인다`처럼 완곡하게 써도 근거 없는 추측을 추가하지 않는다. 문장을 매끄럽게 고치면서 불확실성을 없애거나 수치를 추가하지 않는다.
- 한 문장에 작업·효과·향후계획을 길게 이어 붙이지 않는다. 같은 사실을 요약와 본문에서 긴 문장으로 반복하지 않는다.
- 표·그림 캡션은 무엇을 보여주는지 적는다. `혁신적인 변화`, `최적의 흐름` 같은 평가를 제목에 붙이지 않는다.

## 줄일 표현

근거 없이 쓰는 `혁신적`, `획기적`, `시너지`, `가치 창출`, `최적의 솔루션`, `전반적인 고도화`, `성공적으로`, `원활하게`, `효율성과 안정성을 향상` 같은 표현은 구체적인 작업·결과로 바꾼다. 실제 사업명·평가 기준·사용자의 고정 용어이면 유지하고 필요한 설명을 붙인다.

`단순히 …를 넘어`, `…에 그치지 않고`, `결론적으로`, `종합적으로 볼 때`, `중요한 역할을 한다`, `…라고 할 수 있다`처럼 내용 없이 강조하거나 말을 늘리는 문장은 줄인다. `본 문서에서는`, `아래에서는`, `함께 살펴보겠습니다` 같은 작성자 안내를 본문에 반복하지 않는다.

## 고쳐 쓰기 예시

아래는 문체를 설명하기 위한 가상 예시다. 숫자와 작업을 실제 문서의 사실로 재사용하지 않는다.

| 줄일 문장 | 구체적인 문장 |
| --- | --- |
| 혁신적인 개선을 통해 운영 효율성을 획기적으로 향상시켰다. | 중복 조회를 제거했다. 동일 조건에서 평균 처리시간이 20초에서 15초로 줄었다. |
| 안정적인 서비스 운영 기반을 확보했다. | 재시도 횟수를 제한하고 실패 알림을 추가했다. 장애 감소 여부는 운영 반영 후 확인할 예정이다. |
| 다양한 방안을 종합적으로 검토한 결과 2안이 최적의 솔루션이다. | 2안은 기존 서버를 사용할 수 있다. 신규 서버 도입이 필요한 3안보다 적용 일정이 짧다. |
| 향후 지속적인 고도화를 통해 더 큰 가치를 창출할 예정이다. | 2주간 오류 로그를 확인한다. 담당과 시작 일정은 미정이다. |

구체적인 사실이 없으면 예시처럼 채우지 않고 질문한다. 원문의 뜻을 보존하는 것이 표현을 바꾸는 것보다 우선이다.

## 전달 전 확인

각 문장이 새로운 사실·판단 기준·행동을 전달하는지 읽는다. 없으면 지우거나 합친다. 과장, 막연한 개선 효과, 자동으로 붙인 결론 문장, 불필요한 외래어를 줄인다. 필요한 업무·기술 용어는 쉬운 표현으로 설명하되 용어 자체를 억지로 바꾸지 않는다. 템플릿 목차와 합의한 사실은 유지한다.
